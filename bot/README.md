# 📚 Бот школьных лекций

Telegram-бот на **aiogram 3**: преподаватели публикуют красивые афиши лекций (можно с фото),
ученики бронируют места в один клик. Регистрация — один раз: ФИО и класс.

## Что умеет

**Ученик**
- `/start` — разовая регистрация: ФИО → класс (данные видит только лектор);
- 📅 **Лекции** — афиша ближайших лекций: 🟢 есть места · 🔴 мест нет · ✅ ты записан(а);
- карточка лекции с фото, описанием, лектором, местом и счётчиком свободных мест;
- ✅ **Забронировать место** / ❌ **Отменить бронь** — прямо в карточке;
- 🎟 **Мои записи** — куда записан(а);
- 👤 **Профиль** — посмотреть и поправить ФИО и класс;
- автоматические уведомления, если лекцию перенесли или отменили.

**Преподаватель** (ID из `ADMIN_IDS`)
- ➕ **Новая лекция** — мастер из 7 шагов: название → описание → лектор → место → дата и время →
  количество мест → фото. Перед публикацией показывает предпросмотр афиши ровно в том виде,
  в каком её увидят ученики;
- 📢 **Опубликовать и разослать** — афиша уходит всем зарегистрированным с кнопкой брони
  (или 💾 сохранить без рассылки, разослать можно позже);
- 🗂 **Все лекции** — карточка каждой лекции с действиями:
  - 🎟 **Кто записался** — список «ФИО — класс (@username)»,
  - ✏️ **Редактировать** — любое поле, включая фото и дату (записавшимся уйдёт уведомление о переносе),
  - 🚫 **Отменить лекцию** / ♻️ вернуть в расписание — с оповещением записавшихся,
  - 🗑 **Удалить**;
- 📢 **Рассылка** — произвольное объявление всем зарегистрированным.

Места не «уезжают в минус»: бронь выдаётся в транзакции, при аншлаге бот честно скажет,
что мест нет.

## Установка

```bash
cd bot
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
```

В `.env` заполнить:

| Переменная  | Что это                                                             |
|-------------|---------------------------------------------------------------------|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather)                       |
| `ADMIN_IDS` | Telegram ID преподавателей через запятую (свой ID — у @userinfobot) |
| `DB_PATH`   | файл базы, по умолчанию `bot/lectures.db`                           |

Запуск:

```bash
python main.py
```

Бот работает на long polling — ни домена, ни вебхука не нужно, достаточно любого
компьютера или VPS с Python 3.10+.

## Проверка без Telegram

```bash
python selftest.py
```

Прогоняет реальные сценарии (регистрация → создание лекции с фото → бронь → аншлаг →
перенос → отмена → удаление) через диспетчер aiogram с подменённой сессией: токен не нужен,
база создаётся во временном файле.

## Как устроено

```
bot/
├── main.py          точка входа: конфиг, база, диспетчер, polling
├── config.py        чтение .env
├── db.py            SQLite (aiosqlite): users, lectures, bookings
├── states.py        состояния FSM
├── keyboards.py     клавиатуры и callback-data
├── texts.py         тексты и вёрстка карточек
├── views.py         отправка карточек и рассылки
├── utils.py         даты и экранирование
├── selftest.py      прогон сценариев без Telegram
└── handlers/
    ├── common.py    /start, регистрация, профиль, /help, /cancel
    ├── student.py   афиша, бронь, мои записи
    └── admin.py     мастер лекции, правка расписания, списки, рассылка
```

Данные лежат в SQLite-файле: `users` (ФИО, класс), `lectures` (афиша + `photo_file_id`),
`bookings` (уникальная пара «лекция + ученик»).

## Мелочи, о которых стоит знать

- Время лекций — локальное время машины, на которой запущен бот.
- Фото хранится как `file_id` Telegram, сам файл на диск не качается.
- Преподаватели задаются только через `ADMIN_IDS`: кто не в списке — админку не видит.
- Состояния мастера живут в памяти: после перезапуска бота незаконченный черновик пропадёт,
  сохранённые лекции и брони — нет.
